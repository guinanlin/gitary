## 一、背景与目标

### 1.1 项目背景

Gitary 目前是一个基于 Web 技术的应用，运行在浏览器中，通过 `localhost:5173` 提供服务。为了扩大用户群体，提升用户体验，并支持离线使用，我们需要将现有的 Web 应用封装为 Electron 桌面应用。

### 1.2 业务目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| **扩大用户群体** | 提供桌面应用，满足偏好原生应用的用户需求 | 高 |
| **提升用户体验** | 更快的启动速度，更好的系统集成 | 高 |
| **支持离线使用** | 减少对网络的依赖，支持完全离线工作 | 中 |
| **增强文件系统能力** | 直接访问本地文件系统，无需通过 Git API | 高 |
| **快速发布** | 利用现有代码，快速构建桌面版本 | 高 |

### 1.3 技术目标

| 指标 | 目标值 | 说明 |
|------|-------|------|
| **开发周期** | 1-2 周 | 快速验证和发布 |
| **代码复用率** | > 95% | 最大化复用现有代码 |
| **包体积** | < 200MB | 合理的安装包大小 |
| **启动时间** | < 3秒 | 首次启动时间 |
| **内存占用** | < 500MB | 正常运行时的内存占用 |

## 二、产品需求

### 2.1 核心功能需求

#### 2.1.1 基础功能（MVP）

- ✅ **应用启动**：双击图标启动应用，显示主界面
- ✅ **窗口管理**：支持窗口最大化、最小化、关闭
- ✅ **菜单栏**：提供文件、编辑、视图、帮助等菜单
- ✅ **Web 功能完整保留**：所有现有 Web 功能正常工作
- ✅ **文件系统访问**：支持访问本地文件系统（新增能力）

#### 2.1.2 增强功能（后续迭代）

- 🔄 **系统托盘**：最小化到系统托盘，支持快速启动
- 🔄 **全局快捷键**：支持全局快捷键打开应用
- 🔄 **文件关联**：支持关联特定文件类型（如 `.md`、`.excalidraw`）
- 🔄 **自动更新**：支持应用自动更新
- 🔄 **多窗口支持**：支持打开多个窗口

### 2.2 用户场景

#### 场景 1：首次安装和启动

**用户操作**：
1. 下载并安装 Gitary 桌面应用
2. 双击桌面图标启动应用

**预期结果**：
- 应用在 3 秒内启动完成
- 显示与 Web 版本一致的界面
- 所有功能正常工作

#### 场景 2：本地文件编辑

**用户操作**：
1. 通过菜单或快捷键打开本地文件夹
2. 选择本地 Markdown 文件进行编辑
3. 保存文件到本地

**预期结果**：
- 可以直接访问本地文件系统
- 文件读写操作流畅
- 支持实时保存

#### 场景 3：Git 仓库同步

**用户操作**：
1. 连接 GitHub/Gitee 仓库
2. 编辑文件并提交更改
3. 同步到远程仓库

**预期结果**：
- Git 功能与 Web 版本一致
- 支持离线编辑，在线同步
- 网络错误时有友好提示

#### 场景 4：离线使用

**用户操作**：
1. 断开网络连接
2. 继续使用应用编辑本地文件
3. 使用 AI 功能（需要网络）

**预期结果**：
- 本地文件编辑功能正常
- AI 功能提示需要网络连接
- 数据保存在本地 IndexedDB

## 三、技术方案

### 3.1 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    Electron 应用架构                      │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ┌──────────────────┐      ┌──────────────────┐        │
│  │   主进程 (Main)   │◄────►│  渲染进程 (Web)   │        │
│  │                  │ IPC  │                  │        │
│  │  - 窗口管理      │      │  - React 应用     │        │
│  │  - 文件系统      │      │  - 现有 Web 代码  │        │
│  │  - 系统集成      │      │  - UI 渲染        │        │
│  └──────────────────┘      └──────────────────┘        │
│                                                          │
│  ┌──────────────────────────────────────────┐          │
│  │         Preload 脚本 (Bridge)             │          │
│  │  - 暴露安全的 API 给渲染进程               │          │
│  └──────────────────────────────────────────┘          │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 3.4 构建流程

#### 3.4.1 开发模式

```bash
# 1. 启动 Web 应用开发服务器
pnpm --filter @gitary/web dev

# 2. 启动 Electron（连接到开发服务器）
pnpm --filter @gitary/electron dev
```

#### 3.4.2 生产构建

```bash
# 1. 构建 Web 应用
pnpm --filter @gitary/web build

# 2. 构建 Electron 应用
pnpm --filter @gitary/electron build

# 3. 打包安装程序
pnpm --filter @gitary/electron pack
```

### 3.5 文件系统集成方案

#### 方案 A：通过 IPC 访问（推荐）

**实现方式**：
- 主进程提供文件系统 API
- 通过 IPC 通信
- Preload 脚本暴露安全接口

**优点**：
- 安全性高
- 符合 Electron 最佳实践
- 易于控制权限

**代码示例**：
```typescript
// main.ts
ipcMain.handle('fs:readFile', async (event, path: string) => {
  return await fs.promises.readFile(path, 'utf-8');
});

// preload.ts
contextBridge.exposeInMainWorld('electronAPI', {
  readFile: (path: string) => ipcRenderer.invoke('fs:readFile', path)
});
```

#### 方案 B：新增 Electron 文件系统提供者

**实现方式**：
- 在 `xbook.fs` 抽象层新增 `ElectronFileSystemProvider`
- 与现有的 `IndexedDBFileSystemProvider`、`GitRepoFileSystemProvider` 并列

**优点**：
- 复用现有架构
- 统一接口
- 易于切换

### 3.6 安全配置

```typescript
// main.ts
new BrowserWindow({
  webPreferences: {
    nodeIntegration: false,        // 禁用 Node.js 集成
    contextIsolation: true,        // 启用上下文隔离
    preload: path.join(__dirname, 'preload.js'),
    sandbox: false,                // 根据需要配置
    webSecurity: true              // 启用 Web 安全
  }
});
```

## 一、背景与目标

### 1.1 项目背景

Gitary 项目目前采用 pnpm workspace 管理的 monorepo 架构，包含多个应用和共享包：

- **应用包**：
  - `apps/web` - 主 Web 应用
  - `apps/browser-extension/gitary-companion` - 浏览器扩展

- **共享包**：
  - `packages/ai-assistant-core` - AI 助手核心功能
  - `packages/git-auth` - Git 认证库
  - `packages/git-provider` - Git 提供商抽象
  - `packages/rx-bean` - 响应式状态管理
  - `packages/rx-nested-bean` - 嵌套响应式状态
  - `packages/app-toolkit` - 应用工具包

### 1.2 当前问题

#### 1.2.1 构建性能问题

| 问题 | 当前状态 | 影响 |
|------|---------|------|
| **串行构建** | `pnpm -r build` 串行执行所有包 | 构建时间长，无法充分利用多核 CPU |
| **无智能缓存** | 每次全量构建，即使文件未变更 | 重复构建，浪费时间和资源 |
| **手动依赖管理** | 需要手动指定构建顺序（如 `@gitary/web` 依赖 `@dty/ai-assistant-core`） | 容易出错，维护成本高 |
| **CI/CD 效率低** | 每次 CI 都构建所有包 | CI 构建时间长，资源消耗大 |

#### 1.2.2 开发体验问题

| 问题 | 当前状态 | 影响 |
|------|---------|------|
| **启动慢** | `pnpm dev` 需要等待所有依赖构建 | 开发启动时间长 |
| **类型检查慢** | `pnpm -r typecheck` 串行执行 | 类型检查时间长 |
| **无增量构建** | 修改一个包，需要重新构建所有依赖 | 开发迭代效率低 |

#### 1.2.3 具体性能数据

从 `apps/web/package.json` 可以看到：

```json
"build": "pnpm --filter @dty/ai-assistant-core run build && cross-env NODE_OPTIONS=--max-old-space-size=8192 tsc --project tsconfig.json && cross-env NODE_OPTIONS=--max-old-space-size=8192 vite build --config config/vite.config.ts"
```

- 需要手动管理依赖顺序
- 需要设置大内存限制（`--max-old-space-size=8192`）
- 串行执行，无法并行

### 1.3 业务目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| **提升构建速度** | 通过并行构建和智能缓存，大幅减少构建时间 | 高 |
| **改善开发体验** | 更快的启动和热重载，提升开发效率 | 高 |
| **优化 CI/CD** | 减少 CI 构建时间，降低资源消耗 | 高 |
| **降低维护成本** | 自动管理依赖关系，减少手动配置 | 中 |
| **支持未来扩展** | 为项目规模扩大做好准备 | 中 |

## 二、产品需求

### 2.1 核心功能需求

#### 2.1.1 Turbo 集成（MVP）

- ✅ **安装 Turbo**：在根目录安装 `turbo` 作为开发依赖
- ✅ **创建 Turbo 配置**：创建 `turbo.json` 配置文件
- ✅ **迁移构建脚本**：将现有构建脚本迁移到 Turbo pipeline
- ✅ **并行构建支持**：支持多包并行构建
- ✅ **智能缓存**：基于文件哈希的增量构建
- ✅ **依赖图分析**：自动分析和管理包依赖关系

#### 2.1.2 开发体验优化（后续迭代）

- 🔄 **远程缓存**：支持团队共享构建缓存（可选）
- 🔄 **任务过滤**：支持按包过滤任务执行
- 🔄 **性能监控**：集成构建性能监控和分析
- 🔄 **CI/CD 优化**：优化 CI 工作流，利用 Turbo 缓存

### 2.2 用户场景

#### 场景 1：本地开发构建

**用户操作**：
1. 在根目录执行 `pnpm build` 或 `turbo build`
2. 修改某个包的代码
3. 再次执行构建

**预期结果**：
- 首次构建：并行构建所有包，充分利用多核 CPU
- 增量构建：只构建变更的包及其依赖，其他包使用缓存
- 构建时间大幅减少（从 5-10 分钟减少到 30 秒-2 分钟）

#### 场景 2：开发环境启动

**用户操作**：
1. 执行 `pnpm dev` 或 `turbo dev`
2. 修改某个包的代码
3. 观察热重载效果

**预期结果**：
- 启动时间减少 50-75%（从 30-60 秒减少到 15 秒内）
- 只启动变更的包，其他包使用缓存
- 热重载更快，开发体验更流畅

#### 场景 3：类型检查

**用户操作**：
1. 执行 `pnpm typecheck` 或 `turbo typecheck`
2. 修改某个包的代码
3. 再次执行类型检查

**预期结果**：
- 并行执行类型检查，充分利用多核 CPU
- 未变更的包使用缓存，跳过检查
- 类型检查时间减少 50-66%（从 2-3 分钟减少到 1 分钟内）

#### 场景 4：CI/CD 构建

**用户操作**：
1. 提交代码到 Git
2. CI 自动触发构建
3. 查看构建结果

**预期结果**：
- 只构建变更的包及其依赖
- 利用远程缓存（如果配置），进一步加速
- CI 构建时间减少 70-80%（从 10-15 分钟减少到 3 分钟内）

### 2.3 非功能性需求

#### 2.3.1 性能要求

- **构建速度**：全量构建时间减少 60%+，增量构建时间减少 90%+
- **资源利用**：充分利用多核 CPU，并行执行任务
- **缓存命中率**：未变更包的缓存命中率达到 95%+

#### 2.3.2 兼容性要求

- **与 pnpm 兼容**：完全兼容现有 pnpm workspace 结构
- **向后兼容**：保留现有脚本，支持渐进式迁移
- **跨平台支持**：支持 Windows、macOS、Linux

#### 2.3.3 可维护性要求

- **配置简单**：Turbo 配置清晰易懂
- **文档完善**：提供完整的使用文档和迁移指南
- **易于调试**：提供清晰的构建日志和错误信息

## 三、技术方案

### 3.1 技术选型

#### 3.1.1 Turbo

**选择理由**：
- ✅ **高性能**：Rust 编写，性能优异
- ✅ **智能缓存**：基于文件哈希的增量构建
- ✅ **依赖图分析**：自动分析包依赖关系
- ✅ **并行执行**：充分利用多核 CPU
- ✅ **与 pnpm 兼容**：完美支持 pnpm workspace
- ✅ **成熟稳定**：Vercel 维护，广泛使用

**版本选择**：
- `turbo@latest`（当前最新稳定版）

### 3.2 架构设计

#### 3.2.1 Turbo 配置结构

```
turbo.json
├── pipeline
│   ├── build          # 构建任务
│   ├── dev            # 开发任务
│   ├── typecheck      # 类型检查
│   ├── lint           # 代码检查
│   ├── test           # 测试
│   └── clean          # 清理
└── globalDependencies # 全局依赖（如 tsconfig.json）
```

#### 3.2.2 任务依赖关系

```
build 任务依赖关系：
├── packages/ai-assistant-core (无依赖)
├── packages/git-auth (无依赖)
├── packages/git-provider (无依赖)
├── packages/rx-bean (无依赖)
├── packages/rx-nested-bean (无依赖)
├── packages/app-toolkit (无依赖)
└── apps/web (依赖 @dty/ai-assistant-core)
```

### 3.3 实施步骤

#### 阶段 1：基础集成（1-2 天）

1. **安装 Turbo**
   ```bash
   pnpm add -D -w turbo
   ```

2. **创建 `turbo.json` 配置**
   - 定义基础 pipeline
   - 配置构建任务依赖关系
   - 配置输出目录

3. **更新根目录 `package.json`**
   - 添加 Turbo 脚本别名
   - 保留现有脚本（向后兼容）

4. **测试验证**
   - 验证构建功能正常
   - 验证缓存机制工作
   - 验证并行执行

#### 阶段 2：脚本迁移（1 天）

1. **迁移构建脚本**
   - 将 `build:all` 迁移到 `turbo build`
   - 更新各包的构建脚本

2. **迁移开发脚本**
   - 将 `dev` 迁移到 `turbo dev`
   - 配置开发任务的持久化

3. **迁移检查脚本**
   - 将 `typecheck` 迁移到 `turbo typecheck`
   - 将 `lint` 迁移到 `turbo lint`

#### 阶段 3：优化和文档（1 天）

1. **性能优化**
   - 优化缓存配置
   - 调整并行度
   - 优化输出配置

2. **文档编写**
   - 更新 README
   - 编写迁移指南
   - 编写使用文档

3. **CI/CD 集成**
   - 更新 CI 配置
   - 配置远程缓存（可选）

### 3.4 配置示例

#### 3.4.1 `turbo.json`

```json
{
  "$schema": "https://turbo.build/schema.json",
  "globalDependencies": [
    "tsconfig.json",
    "pnpm-workspace.yaml"
  ],
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": [
        "dist/**",
        "build/**",
        ".next/**",
        "*.tsbuildinfo"
      ],
      "env": [
        "NODE_ENV",
        "NODE_OPTIONS"
      ]
    },
    "dev": {
      "cache": false,
      "persistent": true
    },
    "typecheck": {
      "dependsOn": ["^build"],
      "outputs": []
    },
    "lint": {
      "outputs": []
    },
    "test": {
      "dependsOn": ["^build"],
      "outputs": ["coverage/**"]
    },
    "clean": {
      "cache": false
    }
  }
}
```

#### 3.4.2 根目录 `package.json` 更新

```json
{
  "scripts": {
    "dev": "turbo dev",
    "build": "turbo build",
    "build:all": "turbo build",
    "build:fast": "turbo build --filter=@gitary/web",
    "typecheck": "turbo typecheck",
    "lint": "turbo lint",
    "lint:fix": "turbo lint -- --fix",
    "lint:all": "turbo lint",
    "test": "turbo test",
    "clean": "turbo clean"
  }
}
```

### 3.5 风险与应对

#### 3.5.1 潜在风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| **学习曲线** | 团队需要时间熟悉 Turbo | 中 | 提供详细文档和培训 |
| **配置复杂** | 初始配置可能有问题 | 低 | 参考官方文档和最佳实践 |
| **兼容性问题** | 可能与现有脚本冲突 | 低 | 保留现有脚本，渐进式迁移 |
| **缓存问题** | 缓存可能导致构建错误 | 低 | 提供 `--force` 选项清除缓存 |

#### 3.5.2 回滚方案

- 保留现有 `pnpm` 脚本，Turbo 作为增强而非替代
- 如果出现问题，可以立即回退到原有方式
- 所有变更通过 Git 管理，可以快速回滚

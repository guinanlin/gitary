# 文件上传功能需求文档

## 需求概述

### 核心需求

在文件夹树的加号菜单中添加一个"上传文件"选项，用户点击后可以弹出上传对话框，通过拖拽文件或 Ctrl+V 粘贴的方式上传文件到当前选中的目录（或 Git 仓库）。

**预期行为：**
1. 用户点击文件夹树中的加号按钮
2. 在菜单中看到新增的"上传文件"选项
3. 点击"上传文件"后弹出上传对话框
4. 用户可以通过拖拽文件或 Ctrl+V 粘贴的方式上传文件
5. 文件上传到当前选中的目录（或根目录）
6. 文件自动保存到对应的 Git 仓库（GitHub/Gitee/GitCode）或本地存储
7. 文件树自动刷新，显示新上传的文件

### 需求背景

**问题场景：**
- 用户需要将本地文件上传到 Git 仓库中
- 目前只能通过手动创建文件并复制内容的方式
- 对于图片、PDF 等二进制文件，手动上传非常不方便
- 需要一种快捷的方式将文件上传到仓库

**价值主张：**
- **提升效率**：一键上传，无需手动创建文件
- **支持多种格式**：支持文本、图片、PDF 等各种文件类型
- **便捷操作**：支持拖拽和粘贴两种上传方式
- **无缝集成**：与现有的 Git 仓库系统无缝集成

## 需求详细分析

### 功能需求

#### 1. UI 交互需求

**菜单项位置：**
- 位于文件夹树右键菜单或加号菜单的"add"组中
- 与其他新增选项（File、Folder、Markdown、新建会议纪要等）并列显示
- 使用合适的图标（如 Upload、FileUp 等）

**菜单项状态：**
- **正常状态**：显示"上传文件"文字和图标，可点击
- **禁用状态**：在只读空间或没有写权限时禁用

**上传对话框：**
- **标题**：显示"上传文件"或"Upload File"
- **拖拽区域**：支持拖拽文件的区域，有明确的视觉提示
- **提示信息**：显示"拖拽文件到这里，或按 Ctrl+V 粘贴"
- **文件列表**：显示待上传的文件列表，包含文件名、大小、状态等
- **操作按钮**：上传按钮、取消按钮、清除文件按钮

#### 2. 功能逻辑需求

**文件选择方式：**

1. **拖拽上传：**
   - 支持从文件管理器拖拽文件到对话框
   - 支持同时拖拽多个文件
   - 拖拽时显示视觉反馈（高亮边框）

2. **粘贴上传：**
   - 支持 Ctrl+V（Windows/Linux）或 Cmd+V（Mac）粘贴文件
   - 从剪贴板获取文件数据
   - 支持粘贴单个或多个文件

3. **点击选择（可选）：**
   - 可以添加"选择文件"按钮，打开系统文件选择对话框
   - 支持多文件选择

**文件处理：**

1. **文件验证：**
   - 检查文件大小（可以设置最大文件大小限制，如 100MB）
   - 检查文件名是否合法（避免特殊字符）
   - 检查目标目录是否可写

2. **文件上传：**
   - 获取当前选中的目录（如果没有选中，使用根目录）
   - 构建目标文件路径（目录路径 + 文件名）
   - 读取文件内容（文本文件使用 TextDecoder，二进制文件使用 Uint8Array）
   - 调用文件系统 API 写入文件

3. **Git 集成：**
   - 自动检测当前空间的 Git 平台（GitHub/Gitee/GitCode）
   - 通过文件系统提供者写入文件（自动处理 Git 提交或暂存）
   - 如果启用了 staging 模式，文件会被添加到暂存区
   - 如果没有启用 staging 模式，文件会直接提交到仓库

**上传后处理：**

1. **文件树刷新：**
   - 上传成功后刷新文件树
   - 自动展开目标目录
   - 高亮显示新上传的文件

2. **用户反馈：**
   - 显示上传进度（单个文件进度和总体进度）
   - 上传成功显示成功提示
   - 上传失败显示错误提示（包含具体错误原因）
   - 支持取消上传操作

#### 3. 边界情况处理

**文件冲突：**
- 如果目标目录已存在同名文件，提示用户是否覆盖
- 提供重命名选项

**大文件处理：**
- 对于大文件（如超过 50MB），显示警告提示
- 考虑分块上传（如果需要）

**网络错误：**
- 处理网络超时
- 处理上传中断
- 支持断点续传（可选）

**权限问题：**
- 检查当前用户是否有写权限
- 对于只读空间，禁用上传功能
- 对于未授权的 Git 仓库，提示用户授权

### 非功能需求

#### 1. 性能需求

- **上传速度**：取决于网络和 Git 平台 API 限制
- **文件大小限制**：单个文件建议不超过 100MB（可根据 Git 平台限制调整）
- **并发上传**：支持多个文件同时上传（需要控制并发数，避免过多请求）

#### 2. 可靠性需求

- **错误处理**：完善的错误捕获和用户提示
- **网络异常**：处理网络超时、连接失败等情况
- **文件验证**：上传前验证文件完整性

#### 3. 用户体验需求

- **操作简单**：拖拽即上传，无需额外配置
- **反馈及时**：实时显示上传进度和状态
- **可取消**：支持取消正在进行的上传操作

## 技术分析

### 架构理解

#### 1. 文件树菜单架构

**菜单注册机制：**
```
treePluginAddNode.tsx (基础新增菜单)
  └── treePluginAddFileFromTemplate.tsx (模板文件菜单)
      └── viewSystem.addNodeMenuItems() (注册菜单项)
```

**关键发现：**
- 菜单项通过 `viewSystem.addNodeMenuItems()` 注册
- 菜单项可以绑定事件，通过 `eventBus` 触发
- 菜单项有 `group` 属性（如 "add"），用于分组显示
- 菜单项有 `when` 属性，用于条件显示（如 `"type === 'dir'"`）

#### 2. 文件系统架构

**文件写入链路：**
```
文件上传对话框
  └── 读取文件内容 (FileReader API)
      └── fs.writeFile() (xbook文件系统)
          └── SpaceFileSystemProviderProxy
              └── GitRepoFileSystemProvider (Git仓库)
                  └── gitClient.File.add() (Git API)
```

**关键发现：**
- 使用 `xbook.fs.writeFile()` 写入文件
- 通过 `spaceHelper.getUri(spaceId, path)` 构建文件 URI
- 文件系统提供者自动处理 Git 提交或暂存
- 支持 staging 模式（通过 `window.__GITARY_STAGE_MODE__` 控制）

#### 3. 空间和路径管理

**空间信息获取：**
```
TreeView 组件
  └── treeService.getSpace() (获取当前空间)
      └── space.id (空间ID)
      └── space.platform (平台: github/gitee/gitcode)
      └── space.owner (仓库所有者)
      └── space.repo (仓库名)
```

**路径管理：**
```
选中节点
  └── node.path (节点路径，如 "/docs/images/logo.png")
      └── joinPath(parentPath, fileName) (构建完整路径)
```

### 技术实现方向

#### 1. 菜单项注册方案

**方案选择：创建新的 Tree Plugin**

**实现思路：**
1. 创建 `treePluginUploadFile.tsx` 插件
2. 在插件中注册"上传文件"菜单项
3. 监听菜单点击事件，打开上传对话框
4. 处理文件上传逻辑

**技术要点：**
- 参考 `treePluginAddFileFromTemplate.tsx` 的实现
- 菜单项注册到 "add" 组
- 使用合适的图标（从 lucide-react 导入 Upload 图标）

#### 2. 上传对话框方案

**方案选择：使用 Modal/Dialog 组件 + 自定义上传组件**

**实现思路：**
1. 创建 `FileUploadDialog` 组件
2. 使用 Dialog 组件作为容器
3. 实现拖拽区域（使用 HTML5 Drag & Drop API）
4. 实现粘贴功能（监听 paste 事件）
5. 实现文件列表展示和上传逻辑

**技术要点：**
- 使用 `@/common/components/ui/dialog` 作为对话框容器
- 使用 HTML5 Drag & Drop API 处理拖拽
- 使用 Clipboard API 或 paste 事件处理粘贴
- 使用 FileReader API 读取文件内容

#### 3. 文件上传方案

**方案选择：使用现有文件系统 API**

**实现思路：**
1. 读取文件内容（文本文件用 TextDecoder，二进制用 Uint8Array）
2. 构建目标文件路径
3. 调用 `fs.writeFile()` 写入文件
4. 刷新文件树并显示新文件

**技术要点：**
- 使用 `FileReader` API 读取文件
- 文本文件使用 `TextDecoder` 解码
- 二进制文件直接使用 `Uint8Array`
- 使用 `spaceHelper.getUri()` 构建 URI
- 使用 `fs.writeFile()` 写入文件

**文件读取示例：**
```typescript
// 读取文本文件
const text = await file.text();

// 读取二进制文件
const arrayBuffer = await file.arrayBuffer();
const bytes = new Uint8Array(arrayBuffer);
```

### 技术风险分析

#### 1. 潜在风险

**风险 1：文件大小限制**
- **原因**：Git 平台对文件大小有限制（如 GitHub 限制 100MB）
- **影响**：大文件无法上传
- **缓解**：添加文件大小检查，提前提示用户

**风险 2：粘贴文件浏览器兼容性**
- **原因**：Clipboard API 支持有限
- **影响**：某些浏览器可能不支持粘贴文件
- **缓解**：提供拖拽和点击选择作为备选方案

**风险 3：并发上传性能**
- **原因**：同时上传多个大文件可能影响性能
- **影响**：上传速度慢，可能超时
- **缓解**：控制并发数，添加进度提示

**风险 4：Git API 限制**
- **原因**：Git 平台 API 有速率限制
- **影响**：频繁上传可能触发限制
- **缓解**：使用 staging 模式，批量提交

#### 2. 兼容性考虑

**浏览器兼容性：**
- Drag & Drop API：现代浏览器都支持
- FileReader API：现代浏览器都支持
- Clipboard API：需要检查兼容性

**Git 平台兼容性：**
- 支持 GitHub、Gitee、GitCode
- 使用统一的文件系统接口，平台差异已抽象

# 思维导图节点拖动功能问题报告

## 问题概述

在 Mind Flow（思维导图）应用中，节点拖动功能的交互体验存在问题。当前实现虽然可以让节点移动，但拖动过程不平滑，且拖动时会产生意外的副作用，影响用户体验。

## 问题详细描述

### 问题现象

1. **拖动不平滑**：
   - 拖动节点时，节点不能实时、平滑地跟随鼠标移动
   - 拖动过程中存在明显的延迟、卡顿或抖动现象

2. **连线行为异常**：
   - 拖动节点时，连接节点的线条不能平滑跟随节点移动
   - 线条可能出现长度变化（变长或变短）的情况
   - 线条的实时更新不及时，视觉效果不流畅

3. **其他节点受影响**：
   - 拖动单个节点时，其他节点可能发生位置变化
   - 拖动操作可能触发整个布局的重新计算，导致其他节点被重新定位

4. **视图自动调整干扰**：
   - 拖动过程中可能触发视图的自动重置或缩放
   - 导致正在拖动的节点位置偏移或跳动

### 期望效果

1. **节点跟随鼠标移动**：
   - 按住节点并拖动时，节点应该精确跟随鼠标位置移动
   - 鼠标移动到哪里，节点就移动到对应的位置
   - 拖动过程应该流畅、平滑，无延迟或抖动

2. **连线平滑跟随**：
   - 节点拖动时，连接该节点的线条应该与节点同步、平滑地移动
   - 线条在拖动过程中保持视觉连续性，不应出现长度忽长忽短的情况
   - 线条应该实时更新，与节点移动保持同步

3. **只影响当前节点**：
   - 拖动操作应该只影响被拖动的节点及其连线
   - 不应该触发其他节点的位置变化或布局重新计算
   - 其他节点应该保持在原位置不动

4. **操作流畅性**：
   - 整个拖动操作应该非常流畅、丝滑
   - 不应该有卡顿、延迟或视觉上的不连续

## 当前实现状态

### 已实现的功能

1. ✅ 节点可以通过鼠标拖动改变位置
2. ✅ 节点位置可以通过 `manualX` 和 `manualY` 字段持久化保存
3. ✅ 布局算法支持保留手动设置的节点位置
4. ✅ 拖动时区分节点拖动和画布拖动（panning）

### 存在的问题

1. ❌ 拖动时节点不能平滑跟随鼠标位置
2. ❌ 拖动时连线不能平滑跟随节点移动
3. ❌ 拖动时可能触发其他节点的位置变化
4. ❌ 拖动过程中可能出现视图自动调整，影响拖动体验

## 关键问题点

### 1. 坐标转换问题

- 拖动时需要将屏幕坐标（鼠标位置）正确转换为画布坐标（节点位置）
- 需要考虑视图的平移（viewport.x, viewport.y）和缩放（viewport.scale）变换
- 当前坐标转换可能不准确，导致节点位置与鼠标位置不一致

### 2. 实时更新机制

- 拖动过程中需要在鼠标移动时实时更新节点位置
- 当前的更新机制可能存在延迟或频率问题
- 位置更新可能触发不必要的重渲染或布局计算

### 3. 布局算法干扰

- 拖动时不应该触发布局算法的重新计算
- 手动定位的节点应该完全不受自动布局影响
- 其他节点的位置不应该因为某个节点被拖动而改变

### 4. 视图同步问题

- 拖动过程中视图状态应该保持稳定
- 不应该触发自动重置视图的逻辑
- 画布的平移和缩放状态应该保持不变

## 复现步骤

1. 打开一个思维导图文件（`.mindflow.json` 或 `.mindmap.json`）
2. 在画布上找到一个节点
3. 用鼠标点击并按住该节点
4. 拖动鼠标移动节点到新位置
5. 观察拖动过程中的行为

### 预期行为

- ✅ 节点平滑跟随鼠标移动
- ✅ 连线平滑跟随节点移动，长度保持不变
- ✅ 其他节点位置不变
- ✅ 整个操作流畅无卡顿

### 实际行为

- ❌ 节点移动不平滑，有延迟或抖动
- ❌ 连线可能变长变短，更新不及时
- ❌ 其他节点可能发生位置变化
- ❌ 操作过程中可能有卡顿或视图跳动

## 技术细节

### 节点拖动流程

1. **鼠标按下**（onMouseDown）：
   - 检测是否在节点上按下鼠标
   - 计算初始拖拽偏移量
   - 开始拖动状态

2. **鼠标移动**（onMouseMove）：
   - 监听全局鼠标移动事件
   - 将屏幕坐标转换为画布坐标
   - 更新节点位置

3. **鼠标释放**（onMouseUp）：
   - 结束拖动状态
   - 保存最终节点位置

### 坐标系统

- **屏幕坐标**：鼠标在浏览器窗口中的像素位置（clientX, clientY）
- **画布坐标**：节点在思维导图画布坐标系中的位置（x, y）
- **视图变换**：画布可能有平移（viewport.x, viewport.y）和缩放（viewport.scale）

### 位置更新机制

- 节点位置通过 `updateNodePosition(id, x, y)` 方法更新
- 位置保存在节点的 `manualX` 和 `manualY` 字段中
- 更新会触发状态变更，可能导致重渲染

## 性能考虑

1. **更新频率**：
   - 鼠标移动事件触发频率很高（可能每毫秒多次）
   - 每次位置更新可能触发状态变更和重渲染
   - 需要考虑是否需要节流或防抖

2. **渲染优化**：
   - 拖动过程中可能频繁触发整个画布的重渲染
   - 需要优化渲染性能，减少不必要的计算

3. **布局计算**：
   - 拖动时不应该触发布局算法的重新计算
   - 需要确保布局算法只在必要时运行

## 用户体验要求

### 核心要求

1. **精确跟随**：节点必须精确跟随鼠标位置，移动到哪里就停在哪里
2. **平滑流畅**：拖动过程必须平滑、流畅，无延迟、无抖动
3. **连线同步**：连线必须与节点同步移动，保持视觉连续性
4. **操作稳定**：拖动时不应该影响其他节点或触发视图变化

### 视觉反馈

- 拖动时节点应该有清晰的视觉反馈（如阴影、高亮等）
- 连线应该平滑过渡，不应出现断裂或跳跃
- 整体视觉效果应该专业、流畅

## 总结

当前思维导图的节点拖动功能虽然基本可用，但在用户体验方面存在明显问题。主要问题包括拖动不平滑、连线行为异常、其他节点受影响等。需要重新审视拖动实现机制，特别是坐标转换、实时更新、布局算法和视图同步等方面，以确保拖动操作流畅、精确且不影响其他节点。
